# Harness audit and improvements

Reviewed on 2026-09-13 from commit `5e0346c06c57df7bc30a156643364c797c2aeee4`. The checkout was clean before implementation. This is a TypeScript/Node application with a custom localhost HTTP/SSE UI, an ANSI terminal UI, filesystem tools and local model integrations. It is not a Next.js application. Public-site SEO, accounts, payments and database checks do not apply.

## Confirmed issues addressed

| Problem | Consequence | Change |
| --- | --- | --- |
| Streams could end without a completion marker or silently skip errors | Partial responses could look successful | Strict framing/completion checks, visible stream errors and bounded retries |
| Model requests had no silence or total deadline | A dead runner could leave the session waiting indefinitely | Cancellable silence and total deadlines, including short maintenance deadlines |
| Exhausted empty replies and step limits counted as completion | Automation could accept unsuccessful work | Explicit turn outcomes and unsuccessful headless exits |
| Previous compaction notes were removed before summarization | Decisions available only in an earlier handover disappeared | Prior notes enter the next digest; fallback retains prior narrative |
| Oversized protected tails could still be sent | Silent truncation or backend context errors | Reply reserve, safety margin, complete-group eviction and a hard preflight budget check |
| Manual compaction reused the automatic no-op threshold | `/compact` could claim success without doing anything | Explicit forced compaction |
| LM Studio reasoning was counted despite not being replayed | Unnecessary context pressure and compactions | Provider-aware reasoning accounting |
| Context state was not published during ordinary tool loops | The web meter could remain stale | Update after responses, tools and compaction; distinguish estimates from measurements |
| Restarts could restore unanswered tool calls | Strict providers could reject the next request | Repair complete tool groups and mark uncertain execution outcomes without replaying commands |
| Saved approval IDs could be reused for new commands | Old buttons could approve a different command | Retire saved prompts and advance their identifier sequence |
| Each token consumed a replay slot | One long answer could evict visible history | Coalesce adjacent streaming chunks before saving |
| Resume discarded the backend identity | Identical model names could switch backends | Restore backend as well as model; explicit missing models fail visibly |
| Unsafe preview URL schemes were accepted | A crafted preview could execute in the harness origin | HTTP/HTTPS validation, preview sandbox, blocked self-embedding and no-referrer headers |
| Python syntax checks imported from the repository | A local `py_compile.py` could execute during an automatic check | Isolated Python compilation without execution or bytecode writes |
| Dangling symlinks looked like nonexistent paths | A write could follow a link outside the workspace | Inspect link metadata and fail closed when resolution fails |
| Regex searches ran in the main event loop | A pathological expression could freeze all sessions and cancellation | Cancellable worker with a bounded deadline |
| Pending approval survived a downgrade to read-only | A previously requested command could still execute | Recheck permissions and cancellation immediately before execution |
| Nonzero shell exits looked like successful tool results | Failed verification could receive a green checkmark | Explicit error results and stored command exit outcomes |

## Interaction changes

The web UI removes the ASCII welcome banner, explanatory subtitle, repeated workspace paths, duplicate model labels and permanent keyboard-help row. It uses normal text for navigation and prose, monospace for code, expandable tool activity, one updating plan per turn, and compact model/mode/effort/context controls. Detailed output remains available on demand; errors expand automatically. Mobile panels occupy the available width.

The terminal opens with a single-line identity and a two-row composer. It removes permanent shortcut/path subtitles, completed-thinking lines and routine success lines. Plan updates are compact; `/plan` still displays the full checklist. Turn summaries no longer repeat model and permission information.

## Runtime design

Background compaction is opportunistic. At 60% input-budget pressure, a running command creates an opportunity to summarize a frozen transcript with the same model. The summary has no tools, thinking disabled, at most 700 output tokens and a 45-second deadline. Foreground work cancels unfinished maintenance. A prepared result is applied only if its source prefix still matches, it shrinks the prompt sufficiently, and the unsummarized suffix remains intact.

A per-server inference queue prevents simultaneous maintenance and coding requests within this process. Foreground jobs cancel active optional jobs; optional jobs are deferred when the server is already busy. This also covers automatic session titles. It deliberately does not assume that a second model or extra KV cache fits in memory.

Automatic compaction starts at 80% of usable input capacity. Cheap eviction comes first. If a summary is necessary, deterministic state accompanies the model-written handover. Complete message groups may be evicted if the tail still cannot fit. The current and original requests are preserved; irreducible overflow stops with a diagnosis instead of sending an oversized coding request. Estimates learn conservatively from backend usage and remain estimates between responses.

## API evidence

Implementation was checked against the current official documentation:

- [Ollama native chat](https://docs.ollama.com/api/chat): native tools, thinking, keep-alive, completion marker and token/timing usage.
- [Ollama running models](https://docs.ollama.com/api/ps): effective loaded context length.
- [LM Studio model catalog](https://lmstudio.ai/docs/developer/rest/list): loaded model instances and configuration.
- [LM Studio model loading](https://lmstudio.ai/docs/developer/rest/load): explicit context length and echoed allocation for unloaded models.
- [LM Studio chat completions](https://lmstudio.ai/docs/developer/openai-compat/chat-completions): tool-capable compatibility endpoint retained for agent inference.

The native LM Studio chat API is not substituted for the compatibility tool protocol merely because it is newer. Existing model defaults remain authoritative unless the user supplies an explicit context or reasoning setting.

## Validation and limits

This records the initial audit pass. The subsequent [complex-game lifecycle test](lifecycle-2026-09-13.md) documents additional fixes, the expanded suite and supervised completion limits.

- Baseline: 52 tests passed.
- Final automated suite: 70 passed, 1 skipped, no failures.
- Expanded tests cover incomplete/malformed/error streams, deadlines, maintenance preemption, compaction continuity and stale-prefix rejection, oversized prompts, interrupted tool recovery, replay retention, stale approvals, revoked permissions, nonzero commands, context shrink, native LM Studio load payloads and cancellable searches.
- An actual Ollama run using `qwen3.8:latest`, an 8k context and thinking off created a CommonJS addition module, wrote positive/negative-input tests, ran them and exited successfully: 2 tests passed, 3 tool calls, about 41 seconds including the initial load/prefill. This is a smoke test, not a comparative performance benchmark.
- A second live run used a 4k context to force pressure: six function modules, an index and a test file; 24 tool calls over 22 coding-model requests; eight compactions; all five plan steps completed; eight tests passed, also independently rerun. It finished in about 21 seconds with the model already warm. The repeatable prompt is in [bench/context-smoke.txt](../bench/context-smoke.txt); run it in a fresh disposable folder with `--ctx 4096 --effort off --mode edit`. Timing is not comparable to the cold 8k run, and coding-token statistics exclude auxiliary summaries.
- Browser inspection used a disposable session fixture to verify the welcome screen, transcript, expanded command output, shortcut dialog, desktop layout and mobile breakpoint. A `javascript:` preview URL was rejected before assigning an iframe source.
- A real interactive terminal session verified startup, the compact composer, slash completion, `/context` and clean `/exit`.
- The production dependency advisory check returned no reported advisories; the application has no runtime dependencies. This does not establish application security.

The dangling-file-symlink regression is skipped on this Windows host because the account cannot create that type of symlink. The code path was inspected; the test remains available for hosts with symlink permission. LM Studio model loading and streaming were verified with controlled API responses, not by loading the local 27B model. Long-duration coding quality, repeated model-written summary fidelity, abrupt process death during real side-effecting commands, filesystem races and operating-system containment remain outside this validation. The shell approval scan remains a text scan, not an OS sandbox. Replay is still bounded, and inference queues coordinate one smolcoder process, not independent processes or external clients.
