## Changes under test

The first gated Ollama trial exposed a regression in `1057acd`'s write-payload eviction: it replaced old `write_file` arguments with a string describing omitted code. The model later copied that string into actual source files and spent many calls trying to recover. This trial was stopped and is not a passing result. The first fix turned completed large writes into plain assistant receipts and removed their paired tool results, preserving failed/pending calls and mixed batches. The final representation uses marked harness history records, as explained below. It never manufactures executable arguments. A narrow file-tool guard rejects the exact legacy marker without changing the file.

A second fresh Ollama trial with this fix and reasoning off did not reproduce placeholder corruption. It generated a world lookup that regenerated terrain repeatedly, making one terrain test take about 98 seconds. It repaired several assertion/data issues but repeated slow and timed-out test runs without resolving that cost. The supervising audit stopped this trial before browser acceptance; it is also not a passing result. Subsequent fresh trials use low reasoning. This is a configuration change, so they are not a controlled measurement of the acceptance gate alone.

The first low-reasoning LM Studio trial exhausted three 8,192-token replies entirely on reasoning. One response with thinking off recovered each time, but the repeated cost was substantial. That trial was stopped before completion. Repeated exhaustion now extends the announced recovery interval from one to four, then at most eight responses with thinking off before retrying the selected effort. The model preference is not changed, and the interval resets for a new user turn.

The next low-reasoning LM Studio trial spent many calls reconciling module interfaces, with small edits and evictions repeatedly resetting the individual read guards. It eventually ran tests and was repairing failures when the audit stopped it to install periodic project checks. It is not a completed result. The following fresh trials return to reasoning off, matching the ungated comparison setting.

The next LM Studio run completed its full attempt budget: 231 coding requests, 227 model tool calls, about 1,443 seconds, and six failed acceptance attempts. It automatically repaired build/test failures and block placement, but did not finish a working New World flow. Its buttons captured initial no-op callbacks instead of later callback assignments. Save/reload had passed via an unload auto-save, which was insufficient evidence that Save itself worked. This run is recorded as incomplete.

- `--verify COMMAND` is an explicit headless acceptance gate. The caller's command is immutable during the run and is not another model-visible tool schema. Failures return to the same running agent automatically, including when repeated tool attempts would otherwise pause it. The latest failed check survives compaction as actual evidence. Six acceptance attempts and the model-step budget bound retries; failure or cancellation exits nonzero.
- The repeated-read guard counts observations the model still has. Refetching an evicted result must not trigger a stop. The generic repeated-call guard follows the same rule.
- Without a caller-supplied command, the shared terminal/web/headless agent automatically discovers conventional Node `build`, `test`, and `test:e2e` scripts after file edits. Project-owned scripts only establish the behavior they test.
- After edits, those project scripts also run every 24 tool calls during implementation. Their actual failures survive compaction and return directly to the same agent; these progress checks are separate from the caller's final acceptance budget. This counters cycles of rereading and making small API changes before executing anything. A separate 24-read limit can request acceptance feedback after edits even when previous reads were evicted.
- Once final acceptance has failed, periodic checks use that acceptance command instead of weaker project checks. A green unit test cannot clear a browser failure. A final answer with no intervening tool activity reuses the just-passed acceptance result rather than spending another attempt.
- Background summarization waits 750 ms before inference. Quick shell checks finish without launching an immediately cancelled prefill; longer commands can still overlap with a summary.
- The preview permits pointer lock and confirmation dialogs.
- An earlier LM Studio trial left a backgrounded Vite process holding command pipes open after completion. Managed Bash commands now keep their shell alive while ordinary `&` jobs run, so cancellation can terminate the process tree on Windows. Cancellation and task stop also close inherited pipes. Two real-process regression tests fail before this fix and pass after it; the foreground exit code is preserved.

## Reproduction

Install Playwright separately for the benchmark, or set `PLAYWRIGHT_PATH` to an existing installation. `CHROME_PATH` can name an installed Chrome executable. The harness itself has no new runtime dependency.

```bash
npm run build
mkdir -p playground/fresh-trial playground/trial-logs
export VOXEL_ACCEPTANCE_LOG_DIR="$PWD/playground/trial-logs/acceptance"
# Write the absolute acceptance script path into trial-logs/verify.txt:
# node "/path/to/smolcoder/bench/voxel-acceptance.cjs"
node bench/lifecycle-runner.cjs playground/fresh-trial bench/minecraft-lifecycle-prompt.txt playground/trial-logs --backend=ollama --model=qwen3.8:latest --ctx=65536 --effort=off --max-minutes=35 --verify-attempts=12 --verify-file=playground/trial-logs/verify.txt
node bench/lifecycle-report.cjs playground/trial-logs
```

For LM Studio, use `--backend=lmstudio` and its installed model ID. The same acceptance mechanism is available in the public CLI as `smol PROJECT -p "TASK" --verify "COMMAND"`.

Local evidence lives under `playground/.unattended/`. Generated projects, raw traces and screenshots are ignored by Git.
